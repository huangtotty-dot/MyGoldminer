## 二、根因（代码实证，行号基于 4ca6585）

### F14：尾盘归位链路三处缺陷叠加

**缺陷 1：tail 定量缺 T+1 可用量封顶 —— `main.py:940-943`**

```python
qty = (excess // 100) * 100
_tif = int(getattr(context, "_inflight_sell", {}).get(gm_sym, 0) or 0)
qty = min(qty, max(0, pos_qty - _tif))   # ← 只扣在途，未扣 T+1 不可卖
```

对比仲裁器 `_sell_arbiter` 的正确口径（`main.py:121-126`）：

```python
_avail_raw = holding.get("available")
_avail = pos_qty if _avail_raw is None else int(_avail_raw)   # N25-3: 区分 None 与 0
qty = min(qty, pos_qty, _avail)
qty = min(qty, max(0, min(pos_qty, _avail) - _inflight))
```

tail 路径从未读 `available`，委托量 2100 > 可用 1200，必被柜台拒。

**缺陷 2：tail 无冷却、拒单后逐分钟重试 —— `main.py:962-976`**

仲裁器下单即计虚冷却（`:145-151`），tail 路径下单后**不写 sell_cooldown**；拒单回滚（`:1231-1237`）只回滚 manual_position 与 in-flight，于是下一 bar 重新评估、重新发单、再被拒，循环至收盘。

**缺陷 3：拒单消耗日卖出计数，挤占信号通道 —— `main.py:976` + `:109-110`**

tail 每次下单即 `daily_sell_count[code] += 1`。14:50–14:55 六次（全拒）后计数已达 6 ≥ `max_sell_times_per_stock`(3)。14:56 SELL_HIGH 进入仲裁器后在 `:109-110` **静默 `return False`**——无审计、无通知，信号消失。拒单回滚不减计数。

> SELL_HIGH 消失的直接机制是缺陷 3（日计数耗尽），不是此前猜测的"在途挤占"。缺陷 1/2 是 7 连拒的根源。

### F15：买入路径漏写 order 事件 —— `main.py:1100-1104`

买入分支直接 `order_volume(...)`，此前**没有 `write_order` 调用**；卖出路径 `:132` 有。纯漏行。

## 三、修复方案（不改阈值，均为执行层修正）

### 修改点 1：tail 定量对齐仲裁器口径（`main.py:940-943`）

```python
qty = (excess // 100) * 100
# F14: 与仲裁器同口径——封顶 T+1 可用量并扣除在途
_avail_raw = holding.get("available")     # 需确认 tail 作用域内 holding 可取；
                                           # 不可取则用 context.manual_position[gm_sym]["available"]
_avail = pos_qty if _avail_raw is None else int(_avail_raw)
_tif = int(getattr(context, "_inflight_sell", {}).get(gm_sym, 0) or 0)
qty = min(qty, max(0, min(pos_qty, _avail) - _tif))
if qty < 100:
    continue   # 归位不能的部分（T+1 锁定）属制度约束，静默跳过即可
```

效果：0803 场景下 tail 委托量 = 1200，一笔成交后持仓 2300（含 2300 中 1100 超仓属 T+1 物理不可归位，次日可卖后归位）。

### 修改点 2：tail 下单计虚冷却 + 拒单回滚补回计数（两处）

a) tail 下单成功后（`:962` 附近）补写与仲裁器相同的虚冷却：

```python
try:
    _cd = int(context.engine._get_params(code).get("cooldown_minutes", 30))
except Exception:
    _cd = 30
context.engine.sell_cooldown[code] = now + timedelta(minutes=_cd)
```

b) tail 触发条件 `is_tail and pos_qty > base_ref` 的评估处（`:935`）增加冷却检查，与 `_panic_on_cooldown` 同模式。

c) 拒单回滚（`:1231-1237`）补回计数：

```python
if side == 2 and symbol in context.manual_position:
    ...  # 现有回滚
    # F14: 拒单不消耗日卖出配额/总成交计数
    context.daily_sell_count[code] = max(0, context.daily_sell_count.get(code, 0) - 1)
    context.total_trade_count = max(0, context.total_trade_count - 1)
```

注：仲裁器路径同样受益——拒单不再误耗配额。

### 修改点 3：信号静默丢弃一律留审计（仲裁器各 return False 分支）

仲裁器 `:105-110`（阈值/日计数）、`:95-102`（地板）、`:127-128`（量不足）目前部分静默。统一在丢弃前写：

```python
_audit_write({"event": "sell_skip", "code": code, "action": sig.action,
              "score": sig.score, "reason": "<threshold|daily_count|floor|qty|inflight>",
              "time": str(now)})
```

（`:84-87` inflight_skip 已有，保持。）保证"每个信号必有下文"——C2-3 可解释性不再依赖猜测。

### 修改点 4（F15）：买入路径补 write_order（`main.py:1100` 前）

```python
try:
    write_order(str(now), code, "BUY", qty, cp)
except Exception:
    pass
```
