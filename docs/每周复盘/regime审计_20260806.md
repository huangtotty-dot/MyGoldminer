## 一、结论先行

**当前线上 regime 判定器，实质上不是文档描述的"趋势/环境/Hurst/SHARP 四维评分 + 磁滞状态机"，而是一个"当日（未成形）K 线相对昨收 ±1% 的单条件分类器"，且每天在 09:31 用开盘 1 分钟的数据定死全天。** owner 在手工做T侧体感的"严重干扰买卖"，机制上完全成立。

## 二、致命缺陷 F-R1：状态机无记忆，score 通道永久失效

`index_regime.py:719-720`，`_detect_inner` 每次调用：

```python
prev_regime = IndexRegime.RANGE
days_in_regime = 0
```

磁滞状态机（`_ir_step_regime`）被阉割：

- **进入通道堵死**：score 进入 uni_up/uni_down 需要 |s|≥25 且确认 2 天（`enter_confirm_days=2`），但 `days_in_regime` 每次调用归零 → 计数器最大只能到 ±1 → **任何 score 都进不了 uni_up/uni_down**；
- **退出通道不可达**：prev 恒为 RANGE，"uni→range 退出"分支永远不执行；
- **后果**：`_ir_score_trend` / `_ir_score_env` / Hurst / SHARP 四个评分模块（约 400 行、20+ 参数）对 regime **分类结果零影响**，只影响 telemetry 的 score 数值。实际分类器只剩 K-day 一条路（见 F-R2）。

## 三、致命缺陷 F-R2：K-day 用未成形当日 K 线，±1% 定死全天

机制链（全部已核实）：

1. main.py:736-764：每日**仅在 09:31 首根 bar** 调用一次 `detect_index_regime(as_of=today, force=True, mode="eod")`，结果缓存全天（`_last_ir_date`），盘中不重估；
2. `history_n("SHSE.000001", "1d", 900)` 实盘返回**含当日未成形日线**（main.py:743）；
3. `_ir_kday_eval`（index_regime.py:350-360）：`pct = 最后一根close / 前收 - 1`，**±1.0%**（`k_up_pct/k_down_pct=1.0`，params.py:313-314）即触发 `k_up/k_down`；
4. `_ir_step_regime`：K-day **强制跃迁**，无需任何确认（index_regime.py:589-596）。

合成效果：**09:31 时"当日收盘"就是 09:31 的指数现价——开盘 1 分钟指数 ±1% 的波动，直接决定全天 uni_up/uni_down，进而决定全天买入熔断与回补禁令；下午 V 形反转也不会改判。**

**实证（08-06）**：全天 heartbeat/backtrace 显示 `index_regime=uni_up` 但 `score=-3.888`——分类（K-day 残余）与评分（阴性）公开矛盾，F-R1/F-R2 的实锤。

## 四、中危 F-R3：degraded 静默放行（fail-open）

数据不可用（GM_DATA_READY=False / 缓存缺失 / detect 异常）→ 返回 RANGE + `gate_advice=normal_t`（index_regime.py:107-108, 649-652）：**数据故障 = 悄悄撤掉全部 regime 保护**，仅 print 留痕，不进事件流、watcher 不报警。fail-open 方向本身可讨论，但至少应写 risk 事件让 watcher 推送。

## 五、低危 F-R4：遥测语义混乱 + 死代码

- `days_in_regime` 恒为 ±k_boost(9) 或 0，`switched` 语义失真 → 监控指标不可信，C2-9 需按"K-day 分类器"口径解读；
- `get_regime_position_factor`（uni_down 0.6 / uni_up 1.1）**全项目无调用**——文档宣称的仓位调节从未接线，要么接线要么删；
- qvix / 宽度 / 涨停池三个因子全部降级为空（index_regime.py:124-135），env_score 实质残缺。
