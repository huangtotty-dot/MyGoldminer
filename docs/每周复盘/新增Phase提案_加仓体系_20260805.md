## 四、规则语义草案（待周六逐条确认）

### 4.1 触发条件：回踩重要支撑位不破

需要周六定义清楚的子问题（目前只有思想，没有可执行语义）：

| 子问题 | 候选口径（示例，非定案） |
|---|---|
| "重要支撑位"是什么 | 日线 MA20/MA60、前低、缺口、密集成交区——`daily_pullback_support` 因子现有的判定口径需 Pro 先逆向确认（它已在算，但判定逻辑未审计） |
| "回踩"怎么算 | 盘中最低价触及支撑带（带容差）？收盘价进入支撑带？ |
| "不破"怎么确认 | 盘中触支撑后收回（实时）？还是收 K 确认后次日加（保守）？模拟盘分钟级 bar 支持实时语义，但实时语义假信号率高 |
| 与 BUY_LOW 的边界 | BUY_LOW 是"做T低吸"（锚定日内弱势+评分），ADD_POS 是"趋势仓加码"（锚定日线结构）——同一根 bar 两者同时触发时谁优先？建议 ADD_POS 优先（结构信号强于日内信号），且同一票同日不重复触发 |

### 4.2 数量约束：总仓位分解 → 个股最大仓位

- **上限来源**：三段式仓位配比引擎（position_allocator）按"总资金 × 行情场景"输出各票建议数量范围，取**上限值作为个股最大仓位 `max_pos[code]`**。
- **加仓量公式**：`add_qty ≤ max_pos[code] − 当前持仓[code]`，再叠现金约束、100 股整手、T+1 归位可行性（B-09 教训：买入量不得使当日超仓部分超过 availableNow 可归位能力）。
- **接线方式**：建议 `max_pos` 以配置文件（JSON）落地，每日盘前由 allocator 生成/人工确认，main.py 只读——**不把 Excel 工具嵌进盘中热路径**。
- **更新频率**：资金总量或行情场景切换时重算；日常不变。

### 4.3 继承既有约束（不新建）

uni_down 熔断 / TREND_BREAKDOWN 禁买 / TREND_DOWN 禁加仓 / 尾盘禁买 / 开盘 5 分钟禁买 / 30 分钟买入冷却 / 日买入次数上限——全部继承，不豁免。

## 七、风险与开放问题（周六讨论）

1. **样本稀缺风险**：支撑位回踩是低频事件（周线级），模拟盘 4 票池样本积累慢——是否接受"回放包历史样本 + 模拟盘实战"混合取证？
2. **与 B-07 的联动**：SELL_HIGH 高接问题若立项"回补价格记忆"，加仓通道是否共用同一价格记忆机制？建议周六一并议。
3. **三段式比例本身**：底仓 50-60%/活动仓 20-30%/现金 ≥20% 是 07-27 设计值，当前模拟盘实际现金 73-79% 远偏防御——`max_pos` 按设计比例还是按当前实际资金曲线校准？这直接影响加仓空间。（③类数值议题，记录留 Phase D。）
4. **加仓与做T的活动仓边界**：加仓占用的是活动仓额度还是底仓额度？建议明确：ADD_POS 占**活动仓**（趋势内弹性部分），底仓仅走 base/topup 路径——与三段式语义一致。
