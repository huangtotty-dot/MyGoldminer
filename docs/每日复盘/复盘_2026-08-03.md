### ① 执行 bug（随时修）

**F14：尾盘归位卖出量未封顶 T+1 可用持仓（严重度：高）**
- 现象：14:50:54–14:57:54 每分钟重发 SELL 2100（= 持仓 3500 − base_ref 1400），全部因「冻结 2100 > 可用 1200」被柜台拒单，共 7 笔；sell_rollback ×7 台账处理正确。
- 根因方向：tail 归位计算目标量时未取 `min(超仓量, availableNow)`；今日买入 2300 属 T+1 不可卖，可用仅 1200。且拒单后无冷却/降频，逐分钟重试至收盘。F9 的在途守卫未覆盖 tail 路径。
- 次生损害：14:56 SELL_HIGH 信号（67.1 分）疑似被 tail 在途委托挤占，未发出委托，且 backtrace 无该信号的任何审计记录（决策链断点）。
- 建议修复方向（不改阈值）：① tail 卖出量 = min(超仓量, availableNow)；② 同 code 拒单后置冷却，不再逐分钟重试；③ tail 在途期间 SELL_HIGH 的让行/仲裁逻辑显式化并留审计。
- 验证：构造"当日买入使可用持仓 < 超仓量"用例，断言 tail 委托量 ≤ availableNow 且拒单 ≤1 次；断言 SELL_HIGH 信号必有 order 或 block 审计记录；回归全部测试。

**F15：买入委托 order 事件漏记（严重度：低）**
- 现象：10:30:54 600481 买入在事件桥有 signal 与 fill，无 order 记录；当日全部卖单 order 记录完整。
- 影响：C1-5 通知对账与委托-成交对账出现断点；backtrace 有 buy 事件兜底，审计未完全丢失。
- 建议：核查买入路径事件桥写入分支（买入是否走不同委托函数漏写 order 事件）。
