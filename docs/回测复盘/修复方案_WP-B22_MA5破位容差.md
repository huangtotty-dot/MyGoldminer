## 三、验证中发现并修复

### 修复 1：TARGET_SELL 可覆盖 P0 MA5_EXIT —— [main.py:1648](../../main.py#L1648)（产品真 bug）

- **现象**：test_wp_b22 T3（默认票 tol=0，cp<ma5 应全离）失败——无卖出、无 MA5_EXIT 事件。
- **根因**：TARGET_SELL 分支的优先级保护元组只列 `("PANIC_SELL","TRAIL_SELL","TREND_EXIT")`，**漏了 P0 MA5_EXIT**。浮盈 >10% 且破 MA5 时，TARGET_SELL 会覆盖 MA5_EXIT，把"破位全离"降级为"部分止盈"，违反 B-19"破位全离、优先级最高"设计。PANIC/TRAIL/TREND_EXIT 三处均正确排除 MA5_EXIT，唯独 TARGET_SELL 遗漏。
- **改动**：元组加入 `"MA5_EXIT"`，注释同步标注 P0。
- **实战影响**：修复前，破位时若浮盈 >10%（先涨后破），只触发 75 分 TARGET_SELL 部分离场而非 80 分 MA5_EXIT 全离，持仓残留与"跌破五日均线直接离场"纪律相悖。

### 修复 2：test_wp_b22 T4a 踩 N6 开盘买入隔离 —— 测试时序

- **现象**：T4a（信号通道 BUY_LOW 容差内正常下单 500）失败——无买单。
- **根因**：测试在 09:35 驱动 BUY_LOW，正落在 N6 开盘 5 分钟买入隔离窗（[main.py:1736](../../main.py#L1736)，09:00–09:35）内，信号被隔离，测不到 B-22 买侧容差行为。
- **改动**：T4a 驱动时间 09:35 → 09:36（卖出类 T1/T2 不受影响，保持 09:35）。

### 顺带修复：test_wp_b19 T7 日期漂移（date rot，非产品 bug）

- **现象**：回归中 B-19 20/22，T7a/T7c 红（MA5 恢复 + pos_key 容差）。
- **根因**：T7 用固定模拟日期 2026-08-19 arm 回补记忆，`expire_date` = 卖出日 + 3 交易日 ≈ 08-24；而 `_sell_state_restore` 用**真实 `datetime.now()`** 判过期（[main.py:931](../../main.py#L931)）。真实日期（08-26）已越过 08-24 → 回补被当作"有效期已过"作废。这是测试写就后随真实日期推移产生的 date rot，**产品逻辑正确**（08-19 建的回补记忆到 08-26 本就该过期）。
- **改动**：T7 的 arm 时间改用 `datetime.now()`（真实当下），`expire_date` 恒为未来，测试不再随时间推移变红。
