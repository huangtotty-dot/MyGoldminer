## 一、B-15 根因：三层写入点同频刷屏

每根命中 bar，同一事件被写三遍（0813 各 98 次，一一对应）：

| 层 | 写入点 | 事件 | 去向 |
|---|---|---|---|
| 信号层 | `write_signal`（主流程信号事件写入） | `signal TARGET_SELL` | 事件流 → watcher 推送（0f41692 后关停） |
| 风控层 | `write_risk`（main.py:124，`_sell_arbiter` 地板检查内） | `floor_protection` | 事件流（不进推送） |
| 审计层 | `_audit_write`（main.py:129-131） | `sell_skip reason=floor` | backtrace |

**设计约束（不可动的语义）**：
1. B-14"被拦不耗档"必须保留——地板解除的当根 bar，TARGET 必须能立即成交（安全特性：持仓回升过地板后止盈不得延迟）；
2. 地板/帽拦截本身必须留痕（C2-3 可解释性）——去重 ≠ 删除；
3. O-03 风格去重已有先例（`_check_max_pos_cap` 的 `_max_pos_cap_{code}` 每票每日键，main.py:346）——本包复用同款模式，不发明新机制。

## 二、B-15 修复方案：记录层节流，决策层不动

**总原则：节流只作用于"记录/通知"，信号照常生成、照常进入执行流。**

### 2.1 地板类事件去重（风控层 + 审计层）

`_sell_arbiter` 地板拦截分支（main.py:122-132）加状态键：

```python
_floor_key = f'_floor_logged_{code}_{sig.action}'
_state_sig = f'{pos_qty}_{min_hold}'   # 持仓状态签名
if getattr(context, _floor_key, None) != _state_sig:
    setattr(context, _floor_key, _state_sig)
    write_risk(...)            # floor_protection
    _audit_write(...)          # sell_skip reason=floor
# 同状态重复拦截 → 静默跳过（决策与 return False 不受影响）
```

- 效果：98 → 1 条/日/票/通道；**持仓变化后再次拦截会写新条**（状态签名变了，信息不丢）；
- 日切时键随 `date_reset` 清理（与现有日记键同生命周期）；
- threshold/daily_count/qty 类 sell_skip 量小，不动。

### 2.2 信号事件去重（信号层）

在 `write_signal` 调用处（主流程信号事件写入）前置 mute 检查；mute 标记由**下游拦截点**在拦截时设置：

| 场景 | 设置 mute 的时机 | 清除 mute 的时机 |
|---|---|---|
| TARGET_SELL 地板可预见拦截 | `_sell_arbiter` 地板拦截时置 `_sig_muted_{code}_TARGET_SELL` | pos_qty 变化（成交回调/对账）或日切 |
| BUY_LOW 到顶 | `_check_max_pos_cap` 拦截时置 `_sig_muted_{code}_BUY_LOW`（与 cap 事件同时机，天然每票每日一次） | pos_qty 跌破 ceiling（卖出成交回调）或日切 |

```python
# write_signal 调用处
_mute_key = f'_sig_muted_{code}_{sig.action}'
if not getattr(context, _mute_key, False):
    write_signal(...)          # 事件流（+ watcher 推送源）
```

- 首条信号照常写事件（当日首次触发的信息完整保留）；被拦后同源信号静默；
- **信号对象本身不受 mute 影响**——每 bar 照常生成、照常进 `_sell_arbiter`，地板解除当 bar 立即可卖（约束 1 满足）；
- 边缘情形：profit 跌回 10% 线下再穿线 → 信号重新生成但仍 mute（地板状态未变，无新信息）✓；地板解除后首次触发 → 写事件 + 真实成交 + B-14 置位 ✓。

### 2.3 明确不做的事

- 不在引擎层加"同信号冷却"——那会延迟地板解除后的真实卖出（违反约束 1）；
- 不改 watcher（0f41692 已就位；若日后恢复信号推送，本包保证事件源已去重，轰炸不复发）；
- 不动 B-14 三段式状态机的任何语义。

## 三、B-16 决策分析：000988 权重冲突（owner 三选一）

**现状数学**（0813 盘中口径）：

```
槽位预算 = equity × weight = 191,324 × 20%          = 38,265
max_pos_shares = floor(38,265 / 108.11 / 100) × 100  = 300
ceiling = max(300, base_ref=500)                     = 500   ← WP-E2 保护按设计生效
floor  = 500 × 0.5                                   = 250
```

- ceiling=max(cap, base_ref) 的 max 保护**正常工作**——底仓 500 股没有被预算帽错杀；
- 但 pos 500 = ceiling 500 → **"先买"带宽 = 0**（今日 37 次 BUY_LOW 全拦）；
- "卖-买"循环带宽 = 200 股（500 → 卖 200 → 300 → 回补 200 → 500）仍可用——**做T没有全死，只是不能先买**；
- 冲突实质：**MIRROR 底仓 500 股市值 54,055 = 权益 28.3%，远超 20% 槽位权重**——owner 的底仓意图与槽位预算不兼容。
- 附带事实：今日 cap 拦截实际起了**保护作用**——37 次 BUY_LOW 若放行，将在 107-108 阴跌中分批加仓，收盘浮亏扩大。

| 选项 | 变更 | 效果 | 代价 |
|---|---|---|---|
| ① 接受现状（推荐） | 无 | 000988 只能先卖后买；上涨兑现型做T不受影响 | 下跌抄底（先买）被禁；转③数值观察 |
| ② 提 weight 至 ~35% | 参数 1 行 | cap 600 → 先买空间 100 股 | 单票权重 35% 远超 4 槽均值 25%，集中度显著上升；且 equity 波动时空间不稳 |
| ③ MIRROR 降档 500→200 | 参数 1 行 | base 200 / cap 300 → 先买 100 股、卖-买带宽 100-200 | owner 底仓意图变更；需卖出 300 股落地（人工或 TREND_EXIT 语义外） |

**K3 建议**：①——000988 上市值已超槽位权重，再加先买能力只会放大单票集中度；其做T可走"先卖后买"路径。高价票权重模型（要不要按价格分档调 weight）留 Phase D 统一寻优。若 owner 盘中强需要 000988 先买能力，选②并接受集中度。
