## 四、fix2 建议优先序（只列方向，不动阈值）

1. **接线冷却**：在成交回调（非下单时）调用 `engine.record_trade_action()` —— 一行接线，消灭连续分钟连发。
2. **修卖出通道语义**（本轮最重要）：`is_strong_uptrend` 的 sell_block 需要重审——做T 策略的利润来源就是"卖强"，当前设计把所有强势分钟都禁卖，等于自断经脉。建议：该 block 仅限"指数 uni_up + 个股强趋势"双确认时生效，或改为降分而非禁卖；同时修 `df["low"].min()` 全缓存 bug（应为当日 low）。
3. **修 panic 量纲**：`is_deep_loss` 的 ATR 改用日线级（如 daily_ctx 注入日 ATR），并解开 `sell_score < 40` 的死锁条件（深亏时 panic 不应看正常卖出分脸色）。
4. **仓位上限硬约束**：下单前检查 `市值/(市值+现金) ≤ max_single_position_pct`；sizer 修 `max_buyable=0` 分支返回 0；买入量按可用现金封顶。
5. **买入现金预检**：`qty = min(sizer_qty, floor(available_cash × 0.95 / price / 100) × 100)`，现金不足直接不发单（消灭 33 条拒单）。
6. **审计字段补全**：`no_signal` 增加 `buy_blocks/sell_blocks/last_decision.reason`；buy/sell 事件增加 `action` 字段并与 `on_order_status` 成交回报关联（order_id）；每次回测前清空或按 run_id 分文件写 backtrace.jsonl。
7. **底仓拒单恢复**：status 4/5/6 时将 code 移出 `_base_ordered` 允许重试（限次数）。
8. **开盘 5 分钟信号隔离**：09:30-09:35 的信号用更高的确认门槛或延迟评估（06_T 的 `morning_no_sell_until` 思路），消除开盘量能虚高的失真。

## 五、总体评价

fix1 的工程方向完全正确：状态复位、真实持仓、真实上下文、审计链路、费用口径——这些是"地基"，而且**审计链路立刻体现了价值**（本轮死区三根因全靠 backtrace.jsonl 定位）。团队对审计报告的响应是准确且高效的。

但必须明确：**fix1 验收的是"系统活了"，不是"策略对了"**。当前 KPI（-6.05%、胜率 7.7%、MDD 38.6%）下的策略行为与做T目标（高抛低吸降成本）在语义上是反的：它高吸（开盘追买）、低抛（开盘恐慌割）、从不兑现强势。这不再是工程缺陷，而是信号语义缺陷——恰好是首轮审计中"评分保真"问题（简化引擎 vs 06_T V1.30 场景因子体系）的水面下部分浮出了水面。

**建议路径**：先按第四节 1-4 项出 fix2（预计 0.5~1 天），重跑同一窗口，验收标准不变（T2 八项全过）；通过后再谈 v1.2.0 的评分保真移植。**重申铁律：在卖出语义修复前，不做任何参数寻优。**
