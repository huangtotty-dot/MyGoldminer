# B-18 方案一页纸：回补记忆跨日持久化 + 通道互斥矩阵（合并 B-17）

> 立项：2026-08-18 owner 拍板｜状态：已施工（跨日持久化+互斥矩阵+触发价语义；test_wp_b18 15/15 + WP-B07 19/19 + 全回归绿）｜关联：B-07（WP-B07 已施工）、B-17（已吸收为 M1）、O-12（pos_key 容差，建议同包）

## 1. 背景与问题

WP-B07 回补记忆（`awaiting_buyback`）是**纯日内机制**：TTL 240 分钟 + `_check_date_reset` 跨日清空（engine.py:453-466）。0818 实战暴露机会成本：

| 案例 | armed（0817） | 0818 盘中 | 结果 |
|---|---|---|---|
| 000988 | sell=113.11 target=110.28 | 最低恰好 110.28（−2.5%） | 状态已清，未接回；若接回省 ≈280 元 |
| 600481 | TREND_EXIT sell=4.37 target=4.36 ×2 笔 | **8 次精确触及 4.36** | 状态已清，未回补（且此票 TREND_DOWN，回补本身存疑 → B-17③） |
| 603667 | SELL_HIGH sell=56.61 target=56.50（0818 当日） | 最低 56.50 平触未破 | 日内机制内**正确未触发** ✓ |

结论：日内 TTL 对"当日 V 型回接"有效，对"隔夜低开/次日回踩"完全无覆盖；而模拟盘做T的高抛缺口（603667 300 股、历史 TREND_EXIT 筹码）大量属于后者。

## 2. 设计目标

1. armed 状态**跨日持久化**，次日 INIT 可恢复，回踩目标仍能自动接回；
2. 恢复必须过**安全校验**，防止 stale 状态在错误背景下触发（互斥矩阵，吸收 B-17）；
3. 不破坏现有日内语义：TTL、高接门控、低吸激励全部保留。

## 3. 方案

### 3.1 持久化（复用 WP-B14 机制）

- armed 创建/触发/失效时落盘 `runtime/state/sell_state.json`，挂在对应标的下新增 `_buyback` 字段：
  `{sell_price, qty, target_price, sell_time, sell_action, pos_key, expire_date}`
- INIT 恢复校验（三道闸，任一不过即作废并留痕）：
  1. **pos_key 指纹**匹配（沿用 B-14 机制，容差匹配待 O-12 同包修）；
  2. **有效期**：`expire_date = sell_date + N 个交易日`，**建议 N=3**（覆盖隔夜+短回踩，拒绝死单；参数化 `buyback_persist_days`，进 Phase D 寻优域）；
  3. **互斥矩阵**（见 3.2）。
- 盘中 TTL 语义调整：持久化后"240 分钟"改为"到期日收盘"，日内逻辑不变。

### 3.2 互斥矩阵（吸收 B-17，armed 恢复时 + 盘中触发时各查一次）

| # | 规则 | 触发时动作 |
|---|---|---|
| M1 | 标的日线趋势 = **TREND_DOWN** 且 sell_action = TREND_EXIT | **不恢复/不触发**（趋势破坏退出的票不机械接回）——0818 的 600481 案例下此规则拦住回补，与"不追低"纪律一致 |
| M2 | 标的 TRAIL = ARMED 且当前价处于 peak 回撤区内 | buyback 照常（SELL_HIGH 与 TRAIL 是不同仓位的腿，不互斥）；但若 TRAIL_SELL 已触发（COOLED），buyback 目标按新卖价**重置** |
| M3 | 开盘价距 target 偏离 >2%（跳空） | 延迟到 09:35 开盘缓冲后评估（复用 B-13 闸），避免竞价踩踏接回 |
| M4 | 恢复时 profit 背景为深度亏损（< −8%，PANIC 域） | 不恢复（回补语义是"接回高抛"，不是"摊平亏损"） |

### 3.3 触发价语义明确化

- 改为 **`price <= target_price`**（当前隐含 < 语义下 600481 的 8 次"=4.36 平触"都不会触发；target 本身已是 round(price×gap, 2) 的保守值，平触应算达标）。

### 3.4 留痕与通知

- 恢复/作废/触发全部写 backtrace + events（`buyback_restored` / `buyback_expired` / `buyback_blocked:M1..M4`），飞书推送走成交通道（修复后链路已验证）。

## 4. 测试与验收

- 合成场景 ≥6：跨日恢复触发 / N+1 日过期 / pos_key 不符作废 / M1 趋势互斥拦截 / M3 跳空延迟 / 平触 target 触发；
- 回归 140/140 全绿 + WP-B07 既有 18 场景不破；
- 实战验收：下次 SELL_HIGH/TREND_EXIT 后次日 INIT 日志出现 `buyback_restored`；首个跨日回补成交样本进复盘 ①栏闭合来回口径。

## 5. 工作量与排期

- 预估：持久化 ~40 行（复用 `_sell_state_persist`/INIT 恢复框架）+ 互斥 ~50 行 + 测试 ~80 行；单修包可完成，**建议与 O-12（pos_key 容差匹配）同包**（两处都动 INIT 校验逻辑）。
- 依赖：无；不阻塞 Phase B 样本收集（TRAIL/PANIC 照旧）。

## 6. 风险

- 持久化 armed 遇系统性大跌日批量触发 → M3+M4 + 现金水位闸（buyback 也过 sizer）兜底；
- TREND_EXIT 票 M1 拦死后筹码永久缺口 → 属预期行为（趋势破坏不接回），缺口回补交给新 BASE 建仓信号。
